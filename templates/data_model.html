How the records connect

The relational model behind student identities, academic programmes, invoices, and payments. Primary keys identify records; foreign keys connect them.

PostgreSQL · Relational schema

Core student finance records

CORE ENTITIES
facultiesENTITY
  • PK id
  • name · unique
programmesENTITY
  • PK id
  • FK faculty_id
  • name, award_level
studentsENTITY
  • PK id
  • student_no · unique
  • FK programme_id
  • first_name, last_name, status
academic_semestersENTITY
  • PK id
  • academic_year, semester_number
  • starts_on, ends_on
invoicesENTITY
  • PK id
  • invoice_no · unique
  • FK student_id, semester_id
  • issued_on, due_on, status
invoice_linesENTITY
  • PK id
  • FK invoice_id, fee_type_id
  • description, amount_cents, currency
fee_typesENTITY
  • PK id
  • name · unique
  • description
paymentsENTITY
  • PK id
  • receipt_no · unique
  • FK student_id
  • paid_on, amount_cents, method
payment_allocationsJUNCTION
  • PK payment_id
  • PK invoice_id
  • amount_cents
